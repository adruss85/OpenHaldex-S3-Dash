# CAN relay sample, engine running - the same car as can-relay-sample.txt, but with
# the engine idling rather than off, kept so the per-id list and the values can be
# compared without a car. Decode it with:
#
#   python tools/decode_can_snapshot.py docs/can-relay-sample-engine-running.txt
#
# What it is: the dash's serial console (115200) with 'C' pressed twice, about
# thirty-five seconds apart, while the controller was relaying its chassis bus.
#
# Rig, as reported by the controller's own status packet:
#   chassis      VW PQ, Haldex generation 1
#   controller   DC:1E:D5:82:8B:79 "OpenHaldex-C6", firmware 11.0.4
#   dash         0.5.1, CrowPanel 7.0" ESP32-S3, dashboard on the glass
#   relay        Controller Options > Relay CAN Frames to Gauges =
#                "Each ID up to 10 per second"; Gauges over WiFi (ESP-NOW) on
#   link         WiFi channel 11, RSSI -71..-74 dBm, esp-now 8.9 Hz, air lost 4.9%
#   car state    engine idling: 754 rpm, coolant 77 C, fuel 22 l, speed 0, oil
#                pressure present. Warm engine, stationary. The car is outside and
#                the panel inside, nothing in between this time (a 3D printer there
#                takes air lost from ~5% to 16-26%).
#
# The frame list is the same 17 ids as the engine-off capture: this car does not
# broadcast anything new once it is running, so the extra values come from the same
# messages changing, not from new ones.
#
# Two things in here are questions rather than data, both about boost pressure:
#
#   0x588 Engine_7 carries only 3 bytes (08 00 7E), in every capture from this car,
#   while dbc/vw_pq.dbc declares 8 with BoostPressure at byte 4. The relay sends the
#   controller's own data_length_code, so the car really is sending 3 bytes - which
#   means byte 4, where both dbc/vw_pq.dbc and the controller's own code look for
#   boost, is not in the frame at all.
#
#   0x280 Engine_1 is where the two databases disagree: dbc/vw_pq.dbc has
#   AccelPedalValue_Or_ThrottleValve at bit 40, while the controller's own decoder
#   expects MO_Ladedruck (boost, absolute) at bit 39. On the frame above those bits
#   are zero, which reads as "pedal 0%" or as "0 bar absolute" - and 0 bar absolute
#   is impossible for an idling engine with the throttle shut (that should be about
#   1000 mbar). Pressing the pedal with the ignition on and the engine off tells the
#   two apart: the pedal value moves, boost does not.
#
# The tile values are not affected by either question: those read fixed bytes in
# can_relay.cpp, and they agree with the controller's API on this car.
# ---------------------------------------------------------------------------
